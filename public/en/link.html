A ready-made link for your test management tool

Build an address that opens Walkstamp with the test case, the ticket and the system already filled in. Paste it into Zephyr, Jira, Xray, TestRail, Azure DevOps, qTest — or a spreadsheet.
This is not an integration and it needs nobody's IT department. It is a link. Any tool that can show a link will do, and that is the point: a real integration depends on an API, on permissions and on an approved project; a link works on Monday.

Team plan — activate from the link itself (optional)

Paste the key you were sent. The link then activates the Team plan in the browser of whoever opens it, and arrives with the client name already in the document — nobody on the team has to paste a key. The key is read here in your own browser and is never sent anywhere.

Where not to paste this link: in a ticket anyone in the company can open, in a public channel, in a document shared with the client. Whoever holds the link holds the plan. For those places use the link without the key — it still fills in the test case and the ticket.

The logo does not travel in the link: an address cannot carry a file, and fetching an image off the internet into the document would break the promise that nothing comes in and nothing goes out. It is chosen once, in the tool.

How this fits into Zephyr

Two ways, and both take under a minute per case:

  1. In the test case itself. Paste the link into a test script step or into the description — something like “record the evidence here”. Whoever runs it clicks, records, generates the PDF and attaches it to the execution. The file name already carries the case and the ticket, so it explains itself in the attachment list.
  2. In an automation. If test cycle creation is automated, build the link from the case's own fields. This is the pattern, and it does not change: https://walkstamp.com/app?modelo=evidencia&caso=CT-014&chamado=NAT-1234&sistema=S4P/100

It works the same for Xray, the same for plain Jira, and the same for a shared spreadsheet. That is the advantage of not being an integration.

What the link does and what it does not

It does: open the tool with the fields filled in, in the right language and output model. Whoever runs the test types nothing and chooses nothing — which is why the whole team's evidence comes out in the same shape, with nobody being trained.

It does not: attach anything back into your system, because that would need an API and permissions. The way back is still dragging the file — three seconds, and it works in any tool, including the ones your company will not let you integrate with.

One caution. Whatever goes in the address stays in the browser history of whoever opens it and in the logs of whoever serves the page. System names and ticket numbers are fine; a person's name, an email or any personal data is better left empty and typed on screen.
